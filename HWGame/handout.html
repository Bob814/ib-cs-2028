You are the computer

Today your group is a CPU. A real processor runs billions of tiny steps every second; you will do the very same steps by hand, slowly, on the big screen. Each of you owns one part of the hardware – the Control Unit, the Program Counter, the ALU, the RAM… When your part lights up yellow it is your turn: do exactly one small job, then the next part lights up. Fetch an instruction, decode it, execute it – again and again – until the program says HALT. The app only checks your work; you make it run.

Instruction set card

Every RAM cell holds 3 digits 000–999. Read an instruction as opcode (first digit) | operand (last two digits = an address). Arithmetic wraps around at 1000. If SUB goes below 0 the N (negative) flag switches on; LDA, ADD and INP switch it off.

Opcode 4xx and any other code not in the table is an illegal instruction: the Decoder picks ILLEGAL and the Control Unit presses HALT.

Worked examples

305 = 3 | 05 = STA 05: store the ACC in cell 05.
512 = 5 | 12 = LDA 12: load the value of cell 12 into the ACC.
804 = 8 | 04 = BRP 04: if N is off, jump – the PC becomes 04.
902 = OUT: print the ACC (no operand – leave the box blank when decoding).

Cycle cheat-sheet

Exactly one part is active at a time (thick yellow border). Go = the Control Unit presses Go first (only when the teacher has “Go” switched on). When the CU has just acted itself, its press already counts – it never presses Go twice in a row. The text after each role is the same as the prompt on the screen.

FETCH (every instruction)

  1. Control Unit – press Go to start the FETCH phase Go
  2. Program Counter – send the PC to the MAR Send to MAR
  3. Memory Interface – put the MAR address on the address bus Put on address bus
  4. Control Unit – put READ on the control bus READ
  5. RAM – turn the wheel to the MAR address and place the value on the data bus Place value on data bus
  6. Memory Interface – latch the value from the data bus into the MDR Latch from data bus
  7. Instruction Register – latch the instruction from the MDR Latch from MDR
  8. Program Counter – type PC + 1 and press Set Set

DECODE

  1. Instruction Register – pick the instruction name and type its operand Decode ✓
  2. Control Unit – press Go to start EXECUTE Go

After EXECUTE the CU presses Go again and the loop starts with FETCH.

EXECUTE – per instruction

LDA

  1. Instruction Register – send the operand to the MAR Operand → MAR
  2. Memory Interface – put the MAR address on the address bus Put on address bus
  3. Control Unit – put READ on the control bus READ
  4. RAM – turn the wheel to the MAR address and place the value on the data bus Place value on data bus
  5. Memory Interface – latch the value from the data bus into the MDR Latch from data bus
  6. Accumulator – latch the value from the MDR Latch from MDR

STA

  1. Instruction Register – send the operand to the MAR Operand → MAR
  2. Memory Interface – put the MAR address on the address bus Put on address bus
  3. Accumulator – send the ACC to the MDR Send to MDR
  4. Memory Interface Go – put the MDR value on the data bus Put on data bus
  5. Control Unit – put WRITE on the control bus WRITE
  6. RAM – turn the wheel to the MAR address and store the value from the data bus Store value from data bus

ADD

  1. Instruction Register – send the operand to the MAR Operand → MAR
  2. Memory Interface – put the MAR address on the address bus Put on address bus
  3. Control Unit – put READ on the control bus READ
  4. RAM – turn the wheel to the MAR address and place the value on the data bus Place value on data bus
  5. Memory Interface – latch the value from the data bus into the MDR Latch from data bus
  6. Accumulator – send the ACC to ALU input A Send to ALU A
  7. Memory Interface – send the MDR to ALU input B Send to ALU B
  8. Control Unit – tell the ALU to calculate ALU
  9. ALU – type the result (switch N on if negative) and press Compute Compute
  10. Accumulator – latch the ALU result Latch ALU result

SUB

  1. Instruction Register – send the operand to the MAR Operand → MAR
  2. Memory Interface – put the MAR address on the address bus Put on address bus
  3. Control Unit – put READ on the control bus READ
  4. RAM – turn the wheel to the MAR address and place the value on the data bus Place value on data bus
  5. Memory Interface – latch the value from the data bus into the MDR Latch from data bus
  6. Accumulator – send the ACC to ALU input A Send to ALU A
  7. Memory Interface – send the MDR to ALU input B Send to ALU B
  8. Control Unit – tell the ALU to calculate ALU
  9. ALU – type the result (switch N on if negative) and press Compute Compute
  10. Accumulator – latch the ALU result Latch ALU result

INP

  1. Control Unit – put IN on the control bus IN
  2. I/O – send the next INPUT number to the data bus Send to data bus
  3. Memory Interface – latch the value from the data bus into the MDR Latch from data bus
  4. Accumulator – latch the value from the MDR Latch from MDR

OUT

  1. Control Unit – put OUT on the control bus OUT
  2. Accumulator – send the ACC to the MDR Send to MDR
  3. Memory Interface Go – put the MDR value on the data bus for OUTPUT Put on data bus
  4. I/O – print the value from the data bus Print

BRA

  1. Instruction Register – send the operand to the PC Operand → PC
  2. Program Counter – check the branch target from the IR and press Set Set

BRZ

  1. Control Unit – check ACC and the N lamp – is the branch taken?
  2. Instruction Register – send the operand to the PC Operand → PC (only if taken)
  3. Program Counter – check the branch target from the IR and press Set Set (only if taken)

BRP

  1. Control Unit – check ACC and the N lamp – is the branch taken?
  2. Instruction Register – send the operand to the PC Operand → PC (only if taken)
  3. Program Counter – check the branch target from the IR and press Set Set (only if taken)

HLT

  1. Control Unit – press HALT HALT

Role cards

Role · CU

Control Unit

You own
The Control Unit panel and the CONTROL BUS.
You watch for
Your panel lights up yellow – at the start of every instruction, after decoding, and before most transfers.
You do
  • Press Go to start FETCH, to start EXECUTE after decoding, and to allow a transfer (if the teacher has “Go” switched on). The phase is shown at the top.
  • Press READ or WRITE for memory, IN / OUT for I/O.
  • For ADD/SUB press ALU – the instruction already says which sum to do.
  • For BRZ/BRP look at the ACC and the N (negative) lamp, then press Branch taken or Not taken.
  • Press HALT for 000 – and also for any code that is not in the table (ILLEGAL).
Common mistakes
  • Pressing READ when the instruction needs WRITE (STA).
  • Forgetting that BRZ needs ACC = 0 and N off.
Mini example (warm-up program)
Warm-up, ADD Y: you press READ (step 3), then ALU (step 8).
Role · PC

Program Counter

You own
The Program Counter – the address of the next instruction.
You watch for
The start of every FETCH, the end of every FETCH, and BRA/BRZ/BRP when the branch is taken.
You do
  • FETCH step 2: press Send to MAR – the PC value appears in the MAR.
  • FETCH step 8: type PC + 1 (two digits) and press Set.
  • Branch: the IR puts the target into your box – check it and press Set.
Common mistakes
  • Typing PC + 1 before the instruction was fetched.
  • Typing the branch target on a branch that is not taken.
Mini example (warm-up program)
Warm-up, first fetch: PC = 00 goes to the MAR; at step 8 you type 01.
Role · IR

Instruction Register

You own
The Instruction Register and the Decoder.
You watch for
FETCH step 7 (instruction arrives in the MDR) and DECODE.
You do
  • Press Latch from MDR to copy the instruction.
  • DECODE (bottom of your panel): the first digit is the opcode, the last two the operand. Pick the name, type the operand, press Decode ✓. Codes not in the table are ILLEGAL.
  • EXECUTE: press Operand → MAR (memory instructions) or Operand → PC (branches).
Common mistakes
  • Typing an operand for INP, OUT or HLT (leave it blank).
  • Mixing up 5xx (LDA) and 3xx (STA).
Mini example (warm-up program)
Warm-up: 505 → pick LDA, operand 05.
Role · MAR/MDR

Memory Interface

You own
The MAR (address) and MDR (data) – the CPU’s doors to the buses.
You watch for
Every time an address or a value has to cross a bus.
You do
  • MAR: the PC or IR has already put an address in it – press Put on address bus so RAM can see it.
  • MDR: Latch from data bus after RAM (or INPUT) placed a value.
  • STA and OUT: Put on data bus so RAM can store it or OUTPUT can print it.
  • ADD/SUB: Send to ALU B.
  • Remember: the MDR is the only register that touches the data bus.
Common mistakes
  • Latching the MDR before RAM has placed the value (wait for ACK).
Mini example (warm-up program)
Warm-up, ADD Y: MAR = 06, then MDR = 025.
Role · RAM

RAM

You own
The RAM wheel – 100 cells, but you can only see 5.
You watch for
READ or WRITE lit on the CONTROL BUS.
You do
  • Turn the wheel one cell at a time (drag, mouse wheel or ▲/▼) until the head window is green (head = MAR).
  • READ: press Place value on data bus.
  • WRITE: press Store value from data bus.
  • Every click counts – memory access is slow!
Common mistakes
  • Pressing before the head is green (the buttons stay off).
  • Turning past the address and losing count.
Mini example (warm-up program)
Warm-up, ADD Y: turn to 06 and place 025 on the data bus.
Role · ALU

ALU

You own
The Arithmetic Logic Unit – inputs A and B, the operation, the result.
You watch for
ADD and SUB, step 9 – after the CU pressed ALU. The instruction decides + or −.
You do
  • Work out A + B or A − B.
  • Results wrap around at 1000: 600 + 500 → 100 (overflow).
  • SUB below zero: type 1000 + the result (5 − 10 → 995) and switch N on.
  • Press Compute.
Common mistakes
  • Forgetting the N flag on a negative result.
  • Leaving N on for a positive result.
Mini example (warm-up program)
Warm-up: A = 020, B = 025, + → type 045, N off.
Role · ACC

Accumulator

You own
The Accumulator (ACC) and the N lamp. N = Negative flag: it lights when a SUB result went below zero.
You watch for
The end of LDA, ADD, SUB and INP; the start of STA and OUT.
You do
  • LDA and INP: Latch from MDR. ADD/SUB: Latch ALU result.
  • ADD/SUB: Send to ALU A first.
  • STA and OUT: Send to MDR – the ACC never touches the data bus itself.
Common mistakes
  • Pressing “Latch ALU result” on LDA/INP (the value is in the MDR), or vice versa.
Mini example (warm-up program)
Warm-up: LDA X → ACC = 020; ADD Y → ACC = 045.
Role · I/O

I/O

You own
The INPUT tray, the OUTPUT tray and Storage (disk).
You watch for
IN or OUT lit on the CONTROL BUS.
You do
  • Before the run: type numbers into INPUT and press Add; load a program from Storage.
  • IN: press Send to data bus – the first number in the tray goes to the MDR.
  • OUT: press Print – the value is added to the OUTPUT tray.
Common mistakes
  • Forgetting to put enough numbers in the INPUT tray.
Mini example (warm-up program)
Warm-up: OUT prints 045.

Glossary

CPU (Central Processing Unit)
The chip that fetches, decodes and executes instructions. Here: CU, PC, IR, MAR, MDR, ACC and ALU.
CU (Control Unit)
Directs every step: sends control signals (READ, WRITE, IN, OUT) and decides branches.
ALU (Arithmetic Logic Unit)
Does the calculations (in LMC: + and −). Real ALUs also do MUL, DIV, AND, OR, XOR, NOT.
PC (Program Counter)
Holds the address of the next instruction. Goes up by 1 after each fetch, or jumps on a branch.
IR (Instruction Register)
Holds the instruction being executed, split into opcode and operand.
MAR (Memory Address Register)
Holds the address the CPU wants to use; it drives the address bus.
MDR (Memory Data Register)
Holds the value just read from, or about to be written to, memory; it is connected to the data bus.
ACC (Accumulator)
The working register: results of LDA, ADD, SUB and INP end up here.
N (Negative flag)
A lamp next to the ACC. It lights when a SUB result went below zero (the ACC then shows the wrapped value, e.g. 995 for −5). LDA, ADD and INP switch it off; BRZ and BRP look at it.
Address bus
Carries an address from the CPU to RAM – one way only.
Data bus
Carries values between CPU, RAM and I/O – both ways. Inside the CPU only the MDR is connected to it.
Control bus
Carries signals such as READ, WRITE, IN, OUT, ACK and HALT.
RAM (Random Access Memory)
Main memory: numbered cells holding instructions and data. LMC has 100 cells (00–99).
Volatile
Loses its contents when the power is off. RAM is volatile.
Secondary storage
Non-volatile storage (disk, SSD). Programs live here and are copied into RAM to run.
Clock
Ticks to keep every part in step. Each tick allows one small step – in this game, one micro-step.
Bus width
How many bits a bus carries at once. A 32-bit address bus can address 232 cells (about 4 billion); LMC needs only 100 addresses, so 2 decimal digits are enough.
